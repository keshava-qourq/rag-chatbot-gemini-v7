<!-- sdlc:auto:start overview -->
RAG-chatbot-gemini-v7 is a monorepo generated by the Quorq AI SDLC platform for a document-Q&A chatbot. Users upload documents and ask questions about them. Gemini-2.5-flash generates answers, gemini-embedding-001 creates embeddings, and the app keeps chat history and sessions. The repository is still a scaffold. `frontend/` is a Vite 6 + React 19 + TypeScript SPA styled with Tailwind CSS v4 and routed with react-router-dom v7. Its screens run on seeded sample data. `frontend/src/lib/api.ts` provides an `apiFetch` helper as the seam for connecting screens to real endpoints. `backend/` is a FastAPI 0.115 service that uses SQLAlchemy 2.0, defaults to a local SQLite file, and can be pointed at PostgreSQL through `DATABASE_URL`. Its only implemented route is `GET /health`. It has no models and no routers yet. The `StubResponse` schema is the placeholder that future generated routes will return.
<!-- sdlc:auto:end overview -->

<!-- sdlc:auto:start prerequisites -->
- Node.js with npm (for frontend/)
- Python 3.12 (the version used by backend/Dockerfile)
- Docker with Docker Compose (optional: to run the PostgreSQL 16 database from docker-compose.yml or to build the backend image)
- Playwright Chromium (optional: for e2e tests, installed with `npm run test:e2e:install`)
<!-- sdlc:auto:end prerequisites -->

<!-- sdlc:auto:start setup -->
1. cd backend
2. python -m venv .venv
3. source .venv/bin/activate   # creates backend/.venv, the path playwright.config.ts uses to start the API
4. pip install -r requirements.txt
5. uvicorn app.main:app --reload   # API on http://localhost:8000, using SQLite at ./app.db unless DATABASE_URL is set
6. # in a second terminal, from the repository root:
7. cd frontend
8. npm install
9. npm run dev   # Vite dev server on http://localhost:5173 (the origin the backend allows by default)

<!-- sdlc:auto:start conventions -->
- Frontend imports use the `@/` alias for `src/`, configured in both vite.config.ts and tsconfig.json.
- Vitest component tests sit beside their components under `src/` as `*.test.ts(x)` or `*.spec.ts(x)`. Playwright specs live only in `e2e/`.
- All HTTP calls should go through `apiFetch` in src/lib/api.ts. It reads VITE_API_BASE_URL (default http://localhost:8000) and sends `Authorization: Bearer ${VITE_API_SECRET_KEY}` when that value is set.
- Screens currently render seeded sample data. Connect them to the API one screen at a time.
- TypeScript runs in strict mode, but `noImplicitAny` and `strictNullChecks` are disabled. ESLint and Prettier handle the frontend, and Ruff handles the backend.
- Backend structure: one router module per component in app/routers/. Models subclass `Base` from app/database.py and must be imported via app/models.py so `create_all` registers them. Request-scoped DB sessions come from the `get_db` dependency.
- Unimplemented generated routes return a typed `StubResponse` instead of raising an error, so the OpenAPI document stays complete.
- There are no migrations. Tables are created with `Base.metadata.create_all` at startup, and the code says to replace this with Alembic.
- Configuration comes from environment variables: DATABASE_URL (default sqlite:///./app.db), ALLOWED_ORIGINS (comma-separated, default localhost:5173 and 127.0.0.1:5173), VITE_API_BASE_URL, VITE_API_SECRET_KEY, E2E_BASE_URL. A .env.example exists at the root but its contents were not provided.
<!-- sdlc:auto:end conventions -->

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| Vite or tsc reports it cannot resolve `@/App`. | main.tsx imports `@/App`, and frontend/README.md describes src/App.tsx, src/screens/ and src/lib/brand.ts, but none of these appear in this repository's file tree. Restore or generate these files before running the frontend. |
| Browser calls to the API fail with CORS errors. | The backend only allows http://localhost:5173 and http://127.0.0.1:5173 by default. Set ALLOWED_ORIGINS to a comma-separated list of the frontend's real origin(s) and restart uvicorn. |
| `npm run test:e2e` cannot start the backend web server. | Playwright runs `../backend/.venv/bin/python -m uvicorn ...`. Create backend/.venv and install requirements.txt into it, as shown in the setup steps. |
| Playwright fails because the browser is missing. | Run `npm run test:e2e:install` in frontend/. |
| `npm run build` succeeds but `npm run typecheck` fails. | This is expected: `vite build` does not typecheck. The frontend README says generated screens often fail tsc on untyped `useState({})` values. Add types to those state values. |
| `pytest` raises `ModuleNotFoundError: No module named 'app'`. | Run pytest from the backend/ directory so pytest.ini (pythonpath = .) is picked up. |
| Frontend points at the wrong API. | Set VITE_API_BASE_URL (and VITE_API_SECRET_KEY if needed) before running `npm run dev` or `npm run build`. Without it, the frontend calls http://localhost:8000. |
| Data is stored in SQLite instead of the docker-compose Postgres. | The backend uses sqlite:///./app.db unless DATABASE_URL is set. Start the database with `docker compose up -d db` and set DATABASE_URL to a SQLAlchemy psycopg URL for it, such as postgresql+psycopg://app:app@localhost:5432/app. |
<!-- sdlc:auto:end troubleshooting -->
